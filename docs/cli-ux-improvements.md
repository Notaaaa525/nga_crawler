# CLI 人机交互临时修复与改进方案

| 项 | 内容 |
|---|---|
| 版本 | v1.0（临时修复） |
| 日期 | 2026-10-23 |
| 触发 | 用户按要求运行 `python main.py -h`，截图暴露帮助信息缺少可操作内容 |
| 范围 | 只改“呈现与提示”，不改参数名、默认值、退出码、缓存/TXT/state 契约 |
| 回滚 | 改动集中在 `cli.py` 帮助文案 + `config/auth.py`、`engine.py` 各 1-2 处提示，可单独回退 |

## 1. 从截图看到的问题

截图内容：在 `nga_crawler` 目录执行 `python main.py -h`，输出只有 `usage`、一句描述、
`{crawl,parse}` 与 `-h` 本身。

| # | 现象 | 影响 | 级别 |
|---|---|---|---|
| 1 | 帮助里没有示例；用户不知道 `crawl`/`parse` 各自需要什么参数 | 首次使用必须去翻文档或试错 | 高 |
| 2 | 没有提示凭据配置（`.env` / `NGA_COOKIE`），而这是 `crawl` 100% 会遇到的第一步 | 第一次运行直接退出 2，用户不知所措 | 高 |
| 3 | 没有退出码说明（0/1/2/130 是本项目核心契约） | 脚本集成时无法判断结果 | 中 |
| 4 | 子命令帮助不显示“生效默认值 + 环境变量名”（`--delay`、`--retries`…） | 用户无法判断默认行为，也不知道可被环境变量覆盖 | 中 |
| 5 | `usage:` / `positional arguments:` / `options:` / `show this help message and exit` 英文，其余中文 | 中英混排，观感与可读性差 | 中 |
| 6 | 无 `--version` | 反馈问题/确认版本时无据可依 | 低 |
| 7 | 无子命令时把完整帮助打到 **stdout** 并返回 1，且没有“缺少子命令”的提示 | 管道/脚本里帮助文本与业务输出混在一起；用户不知道错在哪 | 中 |
| 8 | 参数错误只回显 argparse 原文 + usage，没有下一步提示 | 用户不知道用 `-h` 看参数 | 中 |
| 9 | 首次缺凭据的报错是一句话，没给出三种配置方式与获取 Cookie 的路径 | 首次失败后仍需查文档 | 中 |
| 10 | `parse` 空缓存 / 区间为空 / 全是登录墙页时，错误日志只说“没有”，不给下一步动作 | 用户不知道要 `crawl` 还是改 `--cache-dir` | 中 |

## 2. 根因

1. `build_parser()` 只写了 `description` 与最简 `help=`，没有 `epilog`（示例/提示）与本地化文案；
2. 为支持“CLI > 环境变量 > 默认值”，所有可被环境变量覆盖的参数都用了
   `default=None`，argparse 自动生成的默认值展示因此为空，帮助里也没有手写默认值；
3. `add_help=True` 直接使用 argparse 自带英文分节标题与 `-h` 文案；
4. 无子命令与参数错误只走最小实现，未做“下一步”引导；
5. 运行期错误信息只描述事实，没有给出可执行动作。

## 3. 设计原则与约束

1. **零契约变更**：参数名、取值语法、默认值、退出码（0/1/2/130）、缓存/state/TXT 格式全部不变；
2. **帮助即文档**：`-h` 首屏回答“怎么配凭据、怎么跑、怎么看结果、出错怎么办”；
3. **适配终端宽度**：中文按 2 列计算并处理行首/行尾标点禁则，长帮助不横向溢出；
4. **可扫读**：参数帮助统一格式 `说明（默认 X；环境变量 Y）`，示例与提示集中在 `示例:`/`提示:` 段；
5. **脚本友好**：正常帮助走 stdout；用法错误与帮助提示走 stderr，stdout 不混入错误信息；
6. **不引入依赖、不改分层**：仍只用标准库 argparse；`parser`/`render` 不触网纪律不变。

## 4. 实施内容

### 4.1 `cli.py`

| 改动 | 说明 |
|---|---|
| `_ArgumentParser` 本地化 | `format_usage`/`format_help` 把 `usage:` 换成 `用法:`；`_localize_sections()` 把分节标题改为 `位置参数` / `选项` |
| 中文按显示宽度折行 | 自定义 `_HelpFormatter`：全角字符按 2 列计算，长帮助不再横向溢出终端；并做行首/行尾标点禁则处理（`；`、`）` 不落行首，`（` 不落行尾） |
| 自定义 `-h` | `add_help=False` + 中文 `-h, --help`（显示帮助信息并退出） |
| 新增 `-V/--version` | 输出 `NGA 特化爬虫 1.0.0（parser 1.0.0 / fetcher 1.0.0）` |
| 顶层 `epilog` | 示例（含 `.env` 配置写法）、参数/凭据优先级、退出码表、子命令帮助入口 |
| 子命令 `epilog` | `crawl`：续跑语义、凭据前提、限速说明；`parse`：离线、无需 Cookie、`--force` 建议 |
| 参数帮助补全 | 每个参数写明默认值与可用环境变量；`--pages` 补 `all/N/A-B/A-` 语义；`--tid` 显示当前 `DEFAULT_TID` |
| `metavar="<命令>"` | `usage` 从 `{crawl,parse}` 改为更易读的 `<命令> ...` |
| 无子命令行为 | 帮助 + “请指定子命令 crawl 或 parse”提示写 stderr，返回 1 |
| 参数错误提示 | `参数错误: …` + 用法 + `提示：使用 python main.py crawl -h 查看可用参数与示例` |

### 4.2 运行期可操作提示

| 文件 | 改动 |

## 5. 行为变化与兼容性

| 项 | 之前 | 之后 | 兼容性 |
|---|---|---|---|
| `python main.py -h` 文本 | 英文分节 + 无示例 | 中文分节 + 示例 + 退出码 | 仅呈现变化 |
| `python main.py --version` | 报参数错误（退出 1） | 打印版本（退出 0） | 新增能力，不冲突 |
| `python main.py`（无子命令） | 帮助写 stdout，退出 1 | 帮助与提示写 stderr，退出 1 | 退出码不变；stdout 更干净 |
| 参数错误 | 原因 + usage | 原因 + usage + 下一步提示 | 退出码不变 |
| 缺凭据/空缓存报错 | 单句 | 多行、可操作 | 错误类型与退出码不变 |
| 参数名/默认值/缓存/TXT | — | 完全不变 | 无影响 |

## 6. 验收

1. `python main.py -h`：含 `用法:`、`位置参数`、`选项`、`示例`、`退出码`、`.env` 配置提示，无 `usage:`/`options:` 英文分节；
2. `python main.py --version`：打印版本并退出 0；
3. `python main.py crawl -h` / `parse -h`：每个参数含默认值与环境变量名；`--pages` 语法可读；中文长帮助按显示宽度折行，行首不出现 `；`/`）`、行尾不出现 `（`；
4. `python main.py`：stdout 为空，stderr 有“请指定子命令”提示，退出 1；
5. `python main.py crawl --pages 5-3`：stderr 有参数错误 + 用法 + `-h` 提示，退出 1；
6. 首次运行无凭据：stderr 打印三种配置方式与 `.env` 路径，退出 2；
7. 空缓存 `parse`：日志给出“先 crawl / 检查 --cache-dir”的下一步，退出 2；
8. `python -m unittest discover -s tests -t .` 全绿（新增帮助/版本/无子命令用例）；
9. 既有验收项（退出码矩阵、TXT 格式、脱敏、架构 AST）不受影响。
